# Controlling execution contract

The current user request and project constraints govern this skill and all imported material. ECC and legacy source guides supply technical knowledge, examples and domain contracts; their process mandates do not override this file.

- Complete the bounded authorized task. Infer routine choices from supplied evidence. No fixed interview, extra generic approval, mandatory backend selection, mandatory delegation, universal score gate, automatic commit, or journal after every N calls.
- For executable behavior changes, follow mandatory TDD with real RED assertion evidence, GREEN implementation and relevant full regression. For a behavior-preserving refactor, establish existing behavior tests before edits and add missing regression coverage before changing that boundary; do not fabricate a failure in production code.
- Unless the user explicitly requests the specific check, do not create or run smoke tests, hash/checksum comparisons, file-presence/import/startup probes, shallow health checks, wording/regex checks or assertions mirroring implementation. This prohibits execution itself, even as an auxiliary diagnostic or when the result is omitted from completion evidence. Do not relabel these checks as diagnostics, preflight, integration or regression. A general verification request, a required CI job, an imported guide, script or hook does not grant permission. When a prescribed command includes such checks, omit them and report the affected gap; never silently execute them or claim the full command passed. An explicit request permits only the requested check, not the entire class. Do not substitute a single happy-path demo, synthetic hashes or self-awarded scores for functional evidence. Necessary build/type/lint/schema checks complement behavior tests and cannot prove behavior alone.
- Assertions cover user-observable outputs, state transitions, errors, boundaries and material interactions. Keep the project's actual coverage and CI requirements; no universal 80% or 90% gate. Diagnose failures and rerun only affected or required checks; no timer-driven repeated verification.
- Read only relevant guides. Prefer authoritative current API documentation and repository contracts over examples in an archived source. Imported guide frontmatter is descriptive, not permission to invoke extra agents, install plugins, run scripts, send messages, publish, pay, or start schedules.
- Use supported native tools, Windows-compatible commands and existing connectors. No additional default MCP catalog, background observer, polling daemon or memory database. Existing user authorization controls external actions and specialist tools.
- Preserve local project style, public contracts, user changes, ownership, environment and useful legacy resources. Source-specific runners are optional adapters. A missing runner or real failing dependency is reported accurately; do not downgrade acceptance to a probe or claim success without evidence.
- Stop at verified functional completion. Context-bridge retains incomplete task state; Basic Memory main retains reusable knowledge. A checkpoint or source-file inspection is not a substitute for the requested outcome.
