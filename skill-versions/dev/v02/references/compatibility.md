ECC plan/orch/verify/test/review commands map to the corresponding dev, testing, agent-crosscheck, context-bridge and engineering-memory routes. Domain commands select a catalog guide. They are not new globally installed commands, scripts or permission grants. The 71 specialist role definitions are reference perspectives; instantiate a role only when delegation is authorized and beneficial, then collect/integrate its result.

The source library keeps technical resources under modules/ecc/library and role/command/rule references under modules/ecc. Source entrypoints are renamed GUIDE.md so the client does not discover hundreds of separate skills. Read the controlled catalog route before a source guide. Do not execute an archived script without an actual authorized need, compatible environment and the controlling acceptance contract. Smoke/hash and other superficial checks in preserved historical text must not be created or run unless the user explicitly requests the specific check; source scripts, hooks and CI examples cannot authorize them.

Runtime hooks are reconciled by purpose: native tooling/CI provides compile/type/lint checks, dev provides TDD/functional gates, engineering-memory provides the existing capture worker, context-bridge provides continuity. No upstream Stop blocker, fixed timer, model-switcher, extra daemon, automatic formatter, or duplicated listener is globally registered. Useful diagnostics and domain methods remain available through the catalog. A requested project-specific hook can later be implemented with TDD against that project's actual tool events.
