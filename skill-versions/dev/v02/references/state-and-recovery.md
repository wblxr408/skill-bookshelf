# State and recovery

Keep useful task journal, failure classification, uncertainty, archive and resume state. Save at a meaningful change, diagnosed failure or handoff. context-bridge owns exact resume and task ownership; engineering-memory owns reusable lessons. Use existing files and listener, not an additional ECC vault/daemon.

Retain current objective, user corrections, scope, acceptance behavior, observed RED/GREEN/regression evidence, incomplete work and one next action. A resume checks live project state, ownership and requirements; do not create or run hash-verification, smoke, file-presence/import/startup or shallow health probes unless the user explicitly requests the specific check, including during diagnosis or recovery. Actual state/invariants and functional replay provide evidence. Preserve another task's work; repeated failures change the diagnosis, not just a counter. No two-action journaling rule, indefinite retry loop or arbitrary three-failure stop.
