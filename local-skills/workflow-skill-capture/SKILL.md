# Workflow skill capture

Capture a workflow only after identifying a stable trigger, desired outcome, and the non-obvious decisions that make it reliable. Do not turn a one-off preference or temporary workaround into a universal rule.

Create or update a skill in the user's Codex skills directory. Give it a short, action-oriented name and a discriminating description. Keep `SKILL.md` focused on:

- when to use it;
- the outcome it should produce;
- the constraints and stopping conditions that matter;
- links to supporting references or scripts only when they provide repeated concrete value.

Use the skill-creator workflow for structure and validation. Keep the skill automatically discoverable unless the user explicitly requests invocation only by name. After creating it, provide the invocation name and one realistic example request.

For ECC-derived patterns, read ../dev/references/learning.md; learn from verified functional outcomes and explicit user corrections. Scope atomic behaviors to their project before considering broader promotion.
