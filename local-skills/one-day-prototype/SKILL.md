# One-day prototype

Identify the single assumption that would make the idea worth pursuing or abandoning. Build the smallest runnable artifact that makes that assumption observable.

State the target user interaction or technical behavior, the success signal, and explicit exclusions. Prefer familiar local tools and existing project conventions. Avoid production hardening, broad configuration, integrations, and cleanup unrelated to the learning goal.

Deliver the prototype with a short critique: what it demonstrates, what remains unknown, and the next decision the user can make. Do not present a prototype as production-ready without evidence.
