# Technology Stack Evaluator

先用已有需求、代码、部署和决定确定本次选择。保留用户指定与已接受技术；按模块比较可实现同一业务的组合，含复用现有方案的基线。模型 API 不自动选择 Python；基础设施按资源与原生分发需要考虑 Rust/Go。

## 调查范围与证据

逐项筛查 14 维：功能契合、开发速度、运行速度、资源性能、安全、开源生态、可复用性、库质量、有效库供给、可靠性、维护、部署兼容、总成本、迁移退出。先筛硬约束，再按项目优先级取舍；深入调查会改变结论的差异，其余项按名称合并说明状态、原因或未知，不能冒充已做全面评测。

按模块耦合、迁移代价、性能/安全关键性和证据不确定性确定候选范围、重点问题与调查深度，不设统一数量上限。开始时明确本次决策边界和结束条件，只保留能满足硬约束且有实际差异的候选。直接复用仍适用的项目证据；关键的当前版本、兼容、安全等事实查当前官方来源。区分事实、项目实测、估算和未知，给决定性来源与适用条件。速度与资源效率分别看；库供给落实所需能力的合格主备选库，不用包总量或热度代替质量。未知不补默认分，不从分差生成置信概率。

## 渐进加载

默认读本入口即可；遇到决定性疑问，再读 [参考准则](references/evaluation-rubric.md) 的对应节，复用已读内容：
- 首次交付、复用、运维或成本影响选择：读“交付与长期使用”。
- 延迟、冷启动、吞吐或内存影响选择：读“运行速度与资源”。
- 生态、库适配或安全影响选择：读“生态、关键库与安全”。
- 需要正式记录或复杂比较：按需用 [决策模板](references/decision-template.md)，已有 design/decision 只补本次增量。

上游 workflows/metrics/examples、scripts/assets 和原入口仅在对应具体问题时查阅，先定位片段，不整套预载或递归追读。它们保留来源与辅助计算用途，不覆盖本入口；默认评分不作当前事实，不自动运行基准、扫描或额外测试。许可和来源见 LICENSE、UPSTREAM.json。

## 收敛与交付

分批取证，每批检查是否解决决定性缺口、改变候选判断或揭示可信冲突。有关键未知且存在可靠取证路径时继续，不为节省 token 提前结束。新增候选或方向需说明可能改变当前决定的依据；围绕已确定的项目目标，次要发现记为后续，不自动扩展议题。

当前范围内可行方案的核心约束与决定性权衡已足够核实时收敛；新增资料持续不改变判断、只是重复同向佐证，或同因失败且无可行取证路径时停止相应方向。已排除候选仅在淘汰依据被新证据推翻时重开，换词/渠道本身不构成继续理由。

输出推荐、少量决定性差异、其余维度状态、关键库及来源、接受的代价和复评条件。关键硬约束未核实则给有条件方案或明确待决定项，不能宣称通过；只保留会改变决定的未知项及下一步。简单选择简写，不强制 14 行表、固定权重或长报告。

将结果交回调用它的 OpenSpec/dev 或现有决策位置，继续原任务；本技能不反向启动另一轮规划/选型。没有新约束或新决定性证据时复用已有决定。
