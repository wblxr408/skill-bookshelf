# 微信文章到本地知识库

用户提供微信文章并要求阅读、分析或入库时使用。按用户的问题提取内容；仅要求阅读时不要擅自入库。要求入库即授权本地保存，无需再确认。知识库为 Basic Memory 项目 `main`，本地根目录为 `~/basic-memory`。

## 读取正文

先检查本次上下文是否已经对目标返回明确安全策略阻止。该阻止不能通过换工具、代理、浏览器、URL 形式或转存服务规避；这与普通技术失败不同，也不证明所有微信文章均被禁止。当前已知链接 `https://mp.weixin.qq.com/s/dIjVKq0hQcc5ioLaJAYJtA?scene=1` 于 2026-10-08 被浏览器站点安全策略阻止；没有获得策略已解除的证据前，不重试其他抓取途径。可处理用户直接提供的正文或导出件。

对于没有上述阻止的新文章：

1. 优先发现并调用专用 `firecrawl_scrape` 工具。当前工具名为 `mcp__codex_apps__firecrawl_firecrawl_scrape`，名称与参数以当次工具描述为准。请求原始链接、`formats: ["markdown"]`、`onlyMainContent: true`；需要核对当前发布状态时使用 `maxAge: 0`。先取正文，再分析，不以自动 summary 代替来源。当前已核对工具 schema，但微信正文获取尚未端到端实测。
2. 专用工具不可用或出现普通超时、空正文、格式错误时，使用可用网页读取工具或 `browser` 技能的 cua_repl 路线。浏览器已打开并能显示正文时直接读取该页。只对有合理成功预期的替代方式作有界尝试，避免反复重试同一失败路径。
3. 遇到明确安全策略拒绝则停止对该目标的网络读取；登录页、验证码或“环境异常”页面不是正文。遇到需要用户操作的认证或验证时按工具规则交接，不声称完成。
4. 合法读取途径不能取得正文时，准确说明失败类别及已经完成的工作，请用户提供正文、保存的 HTML、PDF 或截图。直接处理用户提供的内容，不要求用户自行整理漏洞。不得把未执行的通道或未经测试的方案称为已解决。

保存文章身份：用户原始 URL、实际标题、公众号/作者、可见发布日期、读取日期和读取方式；缺失字段写未知。核对正文起止、章节、代码和承载关键证据的图片。工具成功状态、标题、摘要和导航文字都不等于全文已取得。只有部分内容时注明覆盖范围，不能宣称漏洞提取完整。必要的中间提取放当前工作区 `work/`，避免无需求复制整篇版权文章进入知识库。

需要解释 `site_status_blocked` 时，读取 Basic Memory 条目 `main/engineering/browser/微信文章拦截来自站点状态检查而非已证实的内容攻击判定`。2026-10-08 已核对其来自 ChatGPT 站点状态判断分支；后端具体分类依据仍未知，不能把“agent”功能字段解释成文章被检测为攻击。

## 提炼与写入

遵循 `~/.codex/skills/engineering-memory/SKILL.md` 的检索及捕获分支。先按文章 URL/ID 和主题检索匹配条目，再读取候选；相同结论更新原条目。保存前区分来源事实、外部核验与自己的建议。

对于安全漏洞，为可独立维护的方案建立条目，正文包含：漏洞成因、触发条件和影响；文章证据位置；解决方案及实施位置；适用范围、版本条件和限制；可执行的验收办法；来源链接与核验日期。CVE、受影响版本、修复版本等向厂商公告、官方仓库等一手来源核对，无法核实就标注未核实。没有 CVE 不自行编造；未做复现或项目验收的方案不标 verified。

文章来源笔记可放 `engineering/security/sources/`，方案放 `engineering/security/solutions/`，独立领域按主题调整。方案采用稳定标题及条目内编号，源笔记通过 Relations 链接方案。写后用 Basic Memory `read_note` 回读确认，同时确认本地文件存在；不能仅凭“调用了写入”宣称已入库。仅在必要的连接故障时加载 engineering-memory 的 connection 分支。
