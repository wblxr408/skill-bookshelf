# Impeccable — unified frontend design

Fuse distinctive art direction and production implementation with product context, UX, accessibility, responsive behavior, and measured browser verification. Honor a pinned visual brief; narrow refinements inherit the existing design. A redesign replaces the visual world while preserving product truth and functional requirements.

The user's default for new sites and substantial redesigns is major-brand production quality: a coherent identity from homepage to small controls, authored composition and media, and immediate, exceptionally fluid interaction. Load the [brand production profile](references/brand-production.md) for that scope; its task-specific direction overrides generic aesthetic defaults, while functional and accessibility constraints remain. A local fix follows the incumbent brand and loads only the relevant detail.

Read [the execution contract](references/fusion-policy.md), then choose one route:

| Request | Read next |
|---|---|
| New site/page identity or substantial redesign | [brand production](references/brand-production.md), then only its relevant reference, motion, or component branch |
| Ordinary implementation within an established identity | [design-and-build](references/design-and-build.md) |
| Existing command: shape, init, document, extract, critique, audit, polish, bolder, quieter, distill, harden, onboard, animate, colorize, typeset, layout, delight, overdrive, clarify, adapt, optimize, live, generate, hooks, doctor, pin/unpin | [command router](references/command-router.md) |
| A precise small component or styling fix | Inspect the target; read [craft-floor](reference/craft-floor.md) immediately before editing and [frontend technique](modules/frontend/PLAYBOOK.md) only when needed |

Use this skill's root `scripts/impeccable.cmd` on PowerShell or `scripts/impeccable` on a compatible shell. Keep cwd at the user's project. Load context once per session when useful; a launcher failure falls back to existing PRODUCT.md/DESIGN.md and current code. Do not let an optional concept-selection UI, fixed question round, or image-generation round block an already clear request. All engine commands remain available when they advance the chosen task.

Inspect desktop and mobile together when applicable, fix observed defects in a batch, and stop after relevant confirmation. Reopen investigation only when the user changes scope or evidence reveals a defect. Route browser work through `$browser`.
