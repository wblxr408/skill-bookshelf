# 丝滑响应、滚动与动效制作

当任务涉及滚动、转场、交互、动态布局或性能时加载。本模块把“极其丝滑”落实为即时反馈、连续运动、稳定内容和设备适配；具体时长与效果由品牌和用户任务决定。

## 动作语言

先写清楚主视觉动作、状态连续性与反馈各自的用途，再建立少量共享时长、缓动和运动尺度。可从以下作者默认值开始调校：按压和反馈约 100–180ms；菜单、切换或布局转场约 180–360ms；首屏或叙事动作约 450–900ms。它们不是行业标准或强制门槛，首屏动作也不能延迟导航和主要操作的可用时间。

入场可以快速到位、缓慢收束；退场更短；拖动跟随指针或手指，释放时根据速度与边界自然落定。弹簧用于适合的形变与落位，文字和高频操作避免反复震荡。被打断的动画从当前状态继续或取消；反复点击、反向滚动、切页和卸载时不重置跳闪、不积累监听器。

按内容安排前后关系。一个有意义的主视觉动作和安静的支持反馈，通常比每段相同的淡入、上移和错峰更有完成度。文本、内容和必要操作在失败、关闭动效或脚本未就绪时仍可访问。

## 滚动与导航

优先让原生滚动自然顺畅，保留触摸惯性、键盘、锚点、浏览器前进后退与恢复位置。需要编排式滚动时，才选择项目现有或适合的工具：单一滚动控制与时钟，明确动画与滚动进度的绑定，避免多套库同时接管。Lenis、GSAP 或 Motion 是按需工具，不是品牌风格本身；接入前核对当前官方文档与版本。

固定段落应有内容理由、明确入口出口和可预期的滚动距离；不靠长时间拦截滚动来证明制作感。横向内容需要可见的方向和等价操作。文字阅读区保持稳定；移动端根据触摸、视口和内容高度重新安排固定与横向段落，必要时采用普通文档流。

## 性能与资产

在高频动画中优先用 transform 与 opacity；避免滚动每帧读写布局或更新整棵组件树。大面积 blur、backdrop-filter、复杂遮罩、阴影与 WebGL 需要控制面积、数量和刷新频率，实际记录后决定保留程度。will-change 按实际需要有限使用。依据 [web.dev 动画指南](https://web.dev/articles/animations-guide) 检查合成、布局与绘制成本。

图片和视频采用适合视口的尺寸、稳定宽高或比例与合理压缩。主要视觉尽早可见，次要媒体和昂贵场景按需加载；视频有可见海报与失败替代，WebGL 有可用的静态或轻量版本。页面隐藏、媒体离屏或效果不需要时暂停。字体选择合适字重与字符覆盖，避免载入切换引发大幅位移。

以代表性设备的刷新率为预算：60Hz 每帧约 16.7ms，120Hz 约 8.3ms，这包括浏览器其他工作，不能全部消耗在动画代码上。观察持续滚动、快速来回、菜单开合、拖拽和切页的长帧、长任务与布局抖动。首次引入高成本效果或真实卡顿时做一次针对性 trace；确认修复后无需反复跑同一套检查。

[Core Web Vitals](https://web.dev/articles/vitals) 的良好体验目标为 LCP ≤2.5s、INP ≤200ms、CLS ≤0.1，以真实访问的第75百分位、分别按移动和桌面判断。作为性能参考与诊断依据使用；本地 trace 或 Lighthouse 样例不能替代现场分布，也不证明持续动画没有掉帧。报告真实设备、条件与实际测得的数据，不用意图宣称“全程60帧”。

## 响应式与减少动效

触摸操作不用 hover 作为唯一入口；拖动与横向滑动处理方向、边界、取消与点击的区别。布局切换、软键盘、浏览器工具栏和方向变化不遮住当前操作。根据场景使用流体排版、容器布局、安全区和合适的视口单位。

遵循 [prefers-reduced-motion](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@media/prefers-reduced-motion)：关闭或减轻惯性接管、视差、大幅位移、循环背景和编排式固定段落，必要内容回到可读的稳定位置。可以保留低强度的状态反馈。针对减少动效状态核对实际使用路径，不能仅在 CSS 中写一条规则便声称完成。
