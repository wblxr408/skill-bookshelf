# audit modes

Modes: quick-audit is a bounded submission screen; deep-review produces technical/methodological/claim-level findings and a revision roadmap; gate makes a blocker-based PASS/FAIL; re-audit checks prior issues against current evidence; polish supplies an audit handoff into writing. Deep-review remains available without a fixed number of agents. Read only the matching mode and critical evidence rules in the audit module.

Use retained audit/claim-map/citation/reference/quote/literature/visual/presubmission scripts for requested or relevant deterministic checks. Generate the original Markdown/HTML report pair, issue JSON, and revision trajectory when the user wants a full structured review. Preserve location IDs, issue lineage, source evidence, claim-to-method/result alignment, novelty and limitations. Do not treat weak stylistic signals as scientific blockers.
