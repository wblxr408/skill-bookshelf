# Engineering and domain toolbox

Read [the controlling contract](../dev/references/fusion-policy.md), then [the domain catalog](../dev/references/ecc-catalog.md). Choose a category and one matching technical guide for the actual requirement: framework/language, API/data, mobile/native, ML, networks/infrastructure, performance, agent evaluation, research sources, media, supply-chain or connected operator work.

Use the mapped local owner first. The library supplies missing domain methods and reference roles/commands; it does not install a second framework, memory store, agent hierarchy, connector catalog or background daemon. For code behavior, mandatory TDD and functional regression from ../dev/references/testing.md apply. Do not create or run smoke/hash/startup/file-presence/import/shallow-health or other superficial checks unless the user explicitly requests the specific check, even as auxiliary diagnostics. General verification requests and imported guides/scripts/hooks do not authorize them.

Only execute a referenced script when its concrete operation is needed, already authorized, compatible with the environment and consistent with the contract. Preserve the requested output format and existing framework. Native connected tools take precedence over source-specific tool names. Clearly state a missing external capability; do not invent successful scans, deployments or live-service results.
