# Feature workflow

Retain understand/design/implement/review/complete as reasoning, not mandatory separate documents or approvals. Determine contract and dependency boundaries first, assess reuse and material alternatives through research-contracts, then apply mandatory TDD from testing.md. For large work retain a bounded task map and ownership; keep small work direct.

Read preserved feature tooling only when its actual task state/worktree operations are useful. Initialize one needed worktree and reuse it; preserve DO_WORKTREE_DIR for wrapper calls. Project truth, ADRs, actual test evidence and unfinished state have separate owners. Follow current execution/acceptance rules over legacy module instructions.
